# JetBrains Islands for Sublime Text 4

> **Visual Fidelity First · Dark & Light · macOS First**
>
> 将 Sublime Text 4 尽可能还原为 IntelliJ IDEA Islands UI 的视觉体验。
>
> 项目目标不是简单制作一个 JetBrains 配色主题，而是建立一套完整、可安装、可切换、可持续维护的 Sublime Text 4 主题方案。

---

## 1. 项目概述

### 1.1 项目名称

**JetBrains Islands for Sublime Text 4**

### 1.2 项目目标

开发一套独立的 Sublime Text 4 主题包，以 IntelliJ IDEA 2025.2 及之后版本的 Islands UI 为主要视觉参考，实现尽可能接近原版 IntelliJ IDEA 的界面体验。

项目必须同时提供：

- Islands Dark
- Islands Light
- 对应的代码配色方案
- 对应的文件类型图标
- 完整的 UI Theme 配置
- 统一的主题切换方案
- 安装、卸载、恢复默认配置的说明

**最终交付要求：安装一次即可使用 Dark 和 Light 两种主题，不需要分别安装两个主题包。**

### 1.3 核心原则

| 原则 | 要求 |
|---|---|
| 视觉还原优先 | 尽可能 1:1 还原 IntelliJ IDEA Islands |
| 双主题 | Dark / Light 必须同时提供 |
| 独立安装 | 一个安装包包含全部资源 |
| 图标质量 | 允许使用成熟的第三方图标资源 |
| 原生兼容 | 遵守 Sublime Text 官方支持的主题机制 |
| macOS 优先 | 优先适配 macOS、Retina 和原生标题栏 |
| 可维护性 | 结构清晰，资源、配置和文档分离 |
| 可验证 | 必须有实际运行和截图对照验收 |

## 2. 视觉参考标准

### 2.1 固定参考版本

主要参考：

**IntelliJ IDEA 2025.2+ Islands UI**

开发过程中必须固定一个具体的 IntelliJ IDEA 版本作为视觉基准，不允许随意混用不同版本的界面设计。

推荐使用同一版本的 IntelliJ IDEA，分别采集：

- Islands Dark
- Islands Light

参考截图应尽可能使用相同的窗口尺寸、屏幕分辨率、缩放比例、工具窗口布局和编辑器内容。

### 2.2 Islands UI 的视觉特征

需要重点还原以下视觉特征：

1. 主窗口、编辑器、工具窗口之间的独立区域感。
2. 窗口各区域之间柔和的背景层次。
3. 圆角、留白、间距和边界处理。
4. 编辑器标签栏与选中标签的视觉状态。
5. 左侧 Project 工具窗口的层次、行高和图标。
6. 顶部工具栏、导航区域和窗口标题栏。
7. 底部状态栏及工具窗口区域。
8. 图标的线条粗细、视觉尺寸和对齐方式。
9. 字体、字重、文字颜色及弱化信息的对比度。
10. Dark 和 Light 两种模式下的视觉一致性。

### 2.3 Islands UI 不是普通深色主题

不能简单地将整个窗口设置成同一种背景色。

应当明确区分：

- 主窗口背景
- 编辑器背景
- 侧边栏背景
- 工具窗口背景
- 标签栏背景
- 状态栏背景
- 浮层和弹出面板背景

深色模式和浅色模式都必须具有清晰但柔和的区域层次。

JetBrains 官方 Islands 主题指南指出，深色模式下主窗口背景应比编辑器和工具窗口背景更亮，浅色模式则采用相反的层次方向；官方还给出了至少 1.20:1 的背景对比度建议。应将其作为设计参考，而不是直接将 JetBrains 参数照搬到 Sublime Text。

## 3. 设计范围与功能模块

整个项目分为四个主要模块。

### 3.1 UI Theme

负责 Sublime Text 的应用界面：

- 窗口和标题栏
- 标签栏
- 侧边栏
- 工具窗口
- 面板
- 快速选择面板
- 状态栏
- 按钮
- 输入框
- 滚动条
- 分隔线
- 选中和悬停状态

UI Theme 是本项目最重要的部分，视觉还原工作应优先投入在这里。

### 3.2 Color Scheme

负责编辑器内部：

- 编辑器背景
- 普通文本
- 关键字
- 字符串
- 数字
- 注释
- 函数
- 变量
- 类型
- 常量
- 运算符
- 错误和警告
- 光标
- 当前行
- 选区
- 搜索匹配
- 括号匹配
- 代码提示和辅助显示

Dark 与 Light 必须分别具有完整的 Color Scheme。

### 3.3 File Icons

负责侧边栏、标签栏等位置的文件和文件夹图标。

要求：

- 覆盖常见编程语言。
- 覆盖常见配置文件。
- 覆盖常见构建工具文件。
- 覆盖常见目录类型。
- 文件夹图标风格统一。
- 图标尺寸和视觉重心一致。
- Dark / Light 下保持足够的辨识度。
- 不允许出现图标模糊、变形或明显的尺寸不一致。

### 3.4 Preferences

负责安装后的推荐配置和主题切换。

应提供：

- Dark 配置模板
- Light 配置模板
- 字体与字号建议
- 标签栏相关设置
- 侧边栏设置
- 状态栏设置
- macOS 相关设置
- 可选的主题切换命令或脚本

不得在安装过程中直接覆盖用户现有的 Preferences.sublime-settings。

## 4. 视觉还原规范

### 4.1 主窗口

重点还原：

- 窗口整体背景
- 原生标题栏
- 主窗口与编辑器区域的层次
- 内容区域的留白
- 工具栏与编辑器之间的间距
- 窗口边缘和圆角所呈现的整体观感

### 4.2 顶部区域

需要研究和还原：

- 标题栏高度
- 标签栏高度
- 标签之间的间距
- 标签圆角
- 标签文字位置
- 活跃标签的视觉强调
- 非活跃标签的文字颜色
- 关闭按钮
- 标签悬停状态
- 多标签排列方式

不要将活跃标签简单处理成传统 IDE 中高亮的大面积色块。应优先参考 Islands UI 的选中标签设计。

### 4.3 左侧 Project 侧边栏

这是视觉还原的重点区域。

需要实现：

- 侧边栏整体背景
- 项目根目录显示
- 文件夹层级
- 文件行高
- 文件名文字颜色
- 文件图标
- 文件夹图标
- 展开和折叠状态
- 当前选中状态
- 鼠标悬停状态
- 缩进距离
- 分隔线和边界处理

特别注意：图标、文字、缩进和行高必须保持视觉平衡，不能只更换图标而忽略布局。

### 4.4 编辑器

重点还原：

- 编辑器背景
- 字体和字重
- 字号
- 行高
- 当前行背景
- 光标颜色
- 选区背景
- 行号颜色
- 缩进参考线
- 括号匹配
- 代码折叠图标
- 搜索结果
- 错误提示和警告提示

### 4.5 底部区域

重点还原：

- 状态栏高度
- 状态栏背景
- 状态文字颜色
- 右侧状态信息
- 编码、换行符、缩进等信息
- 面板和底部工具区域的层次

### 4.6 弹出面板

需要覆盖：

- Command Palette
- Goto Anything
- 搜索面板
- 查找和替换
- 自动补全面板
- 构建输出面板
- 控制台
- 输入面板

这些区域需要与主窗口保持一致的颜色、圆角、文字和选中状态设计。

## 5. Dark / Light 色彩系统

### 5.1 色彩设计原则

不要在实现过程中随意选择颜色。

首先建立一套完整的设计 Token，再将 Token 映射到 Sublime Text 的 UI Theme 和 Color Scheme。

### 5.2 Dark 色彩 Token

建议先建立以下颜色变量：

| Token | 用途 |
|---|---|
| `window.background` | 主窗口背景 |
| `editor.background` | 编辑器背景 |
| `sidebar.background` | 侧边栏背景 |
| `panel.background` | 工具面板背景 |
| `tab.background` | 普通标签背景 |
| `tab.active.background` | 活跃标签背景 |
| `status.background` | 状态栏背景 |
| `border.subtle` | 弱化边界 |
| `text.primary` | 主要文字 |
| `text.secondary` | 次要文字 |
| `text.disabled` | 禁用文字 |
| `accent.primary` | 主强调色 |
| `selection.background` | 选中背景 |
| `hover.background` | 悬停背景 |

### 5.3 Light 色彩 Token

Light 必须独立设计，不能仅仅通过反转 Dark 的颜色得到。

应重点关注：

- 主窗口和编辑器之间的层次。
- 白色区域过多造成的视觉疲劳。
- 边界和分隔线的可见性。
- 文字与背景的对比度。
- 选中状态和悬停状态的辨识度。
- 浮层与主界面的层次关系。

### 5.4 色彩验证

每个颜色 Token 都应有明确用途。

需要验证：

- 正常状态
- 悬停状态
- 选中状态
- 非活跃状态
- 禁用状态
- 焦点状态
- 高对比度显示

禁止出现同一个 UI 元素在不同区域使用不一致的颜色。

## 6. 第三方图标资源

### 6.1 允许使用第三方图标

本项目不要求所有图标都由项目原创。

可以使用成熟、覆盖范围广、维护活跃且许可证允许再分发的开源图标资源。

优先考虑：

- 文件类型图标
- 文件夹图标
- 编程语言图标
- 配置文件图标
- 构建工具图标
- 常见框架和工具图标

可调研的资源方向包括：

- Material Icon Theme
- vscode-icons
- 其他具有明确开源许可证的文件图标集合

这些资源仅作为候选，不能在未核实许可证和实际适配效果前直接打包。

### 6.2 许可证要求

引入任何第三方资源前必须核查：

1. 项目许可证类型。
2. 是否允许商业使用。
3. 是否允许修改。
4. 是否允许再分发。
5. 是否要求保留版权声明。
6. 是否要求附带许可证文件。
7. 是否存在单独授权的图标或字体文件。

每一类第三方资源都应保留来源、许可证和版权声明。

建议在项目中提供：

`THIRD-PARTY-NOTICES.md`

记录：

| 资源 | 来源 | 许可证 | 修改情况 | 声明要求 |
|---|---|---|---|---|
| 文件图标集合 | 实际选定的仓库 | 核实后填写 | 记录 | 按许可证执行 |
| 其他图标 | 实际选定的仓库 | 核实后填写 | 记录 | 按许可证执行 |

**不得直接提取、复制或重新分发 JetBrains 专有图标资源。**

可以借鉴其视觉语言，但图标文件必须来自原创制作或具有合法再分发许可的资源。

### 6.3 图标适配

第三方图标不应直接原样导入后就结束工作。

需要统一：

- 图标尺寸
- 透明边距
- 视觉中心
- 线条粗细
- 色彩饱和度
- 深浅主题适配
- 文件夹图标风格

如果许可证允许修改，可以对资源进行尺寸、透明边距和颜色适配，但必须保留要求的版权和许可证声明。

## 7. Sublime Text 技术实现

### 7.1 三种机制必须分开

Sublime Text 的界面主题、代码配色和文件图标属于不同机制，必须分别实现和验证。

| 机制 | 文件 | 主要职责 |
|---|---|---|
| UI Theme | `.sublime-theme` | 应用界面 |
| Color Scheme | `.sublime-color-scheme` | 编辑器配色 |
| File Icons | `.sublime-file-icons` | 文件和文件夹图标 |

不能认为修改一个 `.sublime-theme` 文件就可以完成全部视觉还原。

### 7.2 UI Theme 实现

应基于 Sublime Text 默认主题进行扩展，优先采用官方支持的主题继承机制。

需要重点研究和实现的控件包括：

- `sidebar_container`
- `sidebar_tree`
- `tree_row`
- `sidebar_heading`
- `file_system_entry`
- `sidebar_label`
- `tabset_control`
- `tab_control`
- `tab_label`
- `status_bar`
- `status_button`
- `panel_control`
- `quick_panel`

实际控件名称、属性和状态必须以当前 Sublime Text 4 版本的官方文档及默认主题资源为准。

不能凭经验编写未经验证的控件名称或属性。

### 7.3 原生能力边界

Sublime Text 与 IntelliJ IDEA 使用不同的 UI 框架。

两者并不是可以任意互换的界面系统。

因此必须区分：

**可以实现或高度近似的部分：**

- UI 颜色
- 标签样式
- 侧边栏样式
- 控件状态
- 文件图标
- 编辑器配色
- 部分间距和尺寸
- 面板视觉风格

**可能存在实现限制的部分：**

- 窗口原生布局
- 系统标题栏
- 原生窗口圆角
- 某些控件的内部结构
- 某些弹出窗口的定位
- 原生菜单和系统级控件
- 不支持自定义的 UI 绘制行为

遇到限制时，应选择最接近的稳定实现。

不得通过不稳定的程序注入、修改 Sublime Text 安装目录内的程序文件或破坏应用签名的方式强行实现视觉效果。

### 7.4 配置兼容性

必须验证：

- 当前 Sublime Text 4 稳定版本。
- macOS 环境。
- 默认主题继承是否正常。
- 主题资源是否被正确加载。
- JSON 配置是否有效。
- 文件图标映射是否有效。
- 不存在资源路径错误。
- 不影响其他已安装插件。

## 8. macOS 专项适配

macOS 是本项目的第一优先级平台。

### 8.1 原生标题栏

优先研究 Sublime Text 在 macOS 下的标题栏样式配置。

需要关注：

- 标题栏背景
- 标题栏文字颜色
- 原生窗口控制按钮
- 标题栏与内容区域的衔接
- 深色和浅色模式下的显示效果

不能为了追求外观而破坏 macOS 原生窗口行为。

### 8.2 Retina

必须在 Retina 显示屏上检查：

- 图标清晰度
- 细线条显示
- 边界像素
- 圆角边缘
- 字体渲染
- 图标透明边距

避免低分辨率图标在 Retina 屏幕上出现模糊。

### 8.3 系统外观

应分别测试：

- macOS 深色外观
- macOS 浅色外观
- Sublime Text 手动切换主题
- 窗口切换和重新启动

不能默认认为 macOS 系统外观变化会自动同步切换 Sublime Text 的 UI Theme 和 Color Scheme。

如果 Sublime Text 的原生配置无法实现完整自动同步，应提供明确、可靠的手动切换方式。

## 10. Dark / Light 一键切换

### 10.1 基本要求

一个安装包包含两个完整主题。

安装后可以切换：

- JetBrains Islands Dark
- JetBrains Islands Light

切换时应同步考虑：

1. UI Theme
2. Color Scheme
3. File Icons（如果两套图标配置确实需要分别切换）
4. 其他必要的主题设置

### 10.2 推荐实现

优先使用 Sublime Text 原生支持的配置机制。

如果原生机制无法将多个设置作为一个原子操作完成，可以提供：

- 两套完整设置模板。
- 可选切换命令。
- 清晰的手动切换说明。

不要为了实现一键切换而引入庞大、没有必要的插件依赖。

### 10.3 用户配置保护

切换时不得：

- 删除用户原有设置。
- 覆盖无关插件配置。
- 修改用户项目文件。
- 重置用户快捷键。
- 擅自更改字体、缩进等与主题无关的个人偏好。

应只修改主题切换所需的设置项，并在文档中说明修改范围。

## 11. 像素级对照开发流程

这是本项目最重要的质量控制要求。

不能只凭肉眼觉得相似就宣布完成。

### 11.1 固定测试环境

首先固定：

- IntelliJ IDEA 参考版本。
- Sublime Text 4 版本。
- macOS 版本。
- 显示器分辨率。
- Retina 缩放设置。
- 窗口尺寸。
- 编辑器字体。
- 字号。
- 侧边栏宽度。
- 工具窗口布局。

### 11.2 建立参考截图

至少采集以下场景：

| 场景 | 对照内容 |
|---|---|
| 主窗口 | 整体布局和背景层次 |
| 顶部区域 | 标题栏、工具栏、标签栏 |
| Project | 文件树、图标、缩进 |
| 多标签 | 活跃与非活跃标签 |
| 编辑器 | 代码配色、行号、光标 |
| Command Palette | 弹出面板 |
| 搜索 | 搜索结果和选中状态 |
| 底部面板 | 控制台、构建输出 |
| 状态栏 | 高度、背景和文字 |
| 全屏 | 窗口空间和布局 |
| 多窗口 | 不同窗口的视觉一致性 |

Dark 和 Light 都必须完成上述对照。

### 11.3 对照维度

逐项比较：

- 背景颜色
- 前景文字颜色
- 圆角
- 控件高度
- 控件宽度
- 行高
- 标签间距
- 内边距
- 外边距
- 图标尺寸
- 图标对齐
- 边界和分隔线
- 选中状态
- 悬停状态
- 阴影和层次

### 11.4 对照工具

可以使用截图对比、透明叠加、差异图等方法辅助检查。

但需要注意：

Sublime Text 与 IntelliJ IDEA 的原生布局和 UI 框架不同，无法保证所有区域像素完全一致。

因此验收重点应当是：

1. 视觉结构一致。
2. 色彩层次一致。
3. 控件比例尽可能一致。
4. 主要视觉元素一致。
5. 无明显不协调区域。
6. 原生交互和稳定性不受影响。

## 13. 必须注意的技术问题

### 13.1 不要混淆 UI Theme 和 Color Scheme

这是最容易出现的问题之一。

修改编辑器配色并不会自动改变 Sublime Text 的侧边栏、标签栏和状态栏。

必须分别实现、分别测试。

### 13.2 不要使用未经确认的控件属性

Sublime Text 主题属性具有明确的支持范围。

编写 `.sublime-theme` 时：

- 先查官方文档。
- 再参考默认主题。
- 使用已确认的控件名称。
- 使用已确认的属性。
- 检查状态选择器。
- 实际加载验证。

不要直接复制其他编辑器的主题配置。

### 13.3 不要假设所有圆角都能实现

不同控件可能支持不同的圆角和边距属性。

如果某个区域不能完全复现 IntelliJ 的圆角效果，应选择最接近的原生方案，不要通过不稳定方式修改窗口。

### 13.4 不要过度使用边框

Islands UI 的重要特点之一是区域之间的柔和融合。

不要给每个控件都增加明显边框。

边界应当服务于层次，而不是让界面变成大量独立方框。

### 13.5 不要让 Dark 和 Light 只是简单反色

两套主题应分别校准。

尤其要关注：

- 主窗口与编辑器的层次。
- 侧边栏文字对比度。
- 活跃标签。
- 弹出面板。
- 文件图标。
- 状态栏。

### 13.6 不要随意引入过多插件依赖

项目应尽可能保持独立。

如果文件图标功能依赖第三方图标包，应优先评估能否合法整合所需资源，避免用户为了完整体验安装大量额外插件。

### 13.7 不要忽略许可证

任何第三方图标、字体、图片或其他资源都必须核实许可证。

不能因为资源可以从 GitHub 下载，就默认允许打包和再分发。

### 13.8 不要破坏用户配置

安装程序、切换脚本和配置模板都必须遵守最小修改原则。

必须提供恢复默认主题的方式。

### 13.9 不要未经验证就发布

配置文件能够解析，不代表 Sublime Text 能够正确加载。

必须实际启动应用验证。

### 13.10 不要为了截图效果牺牲实际体验

主题必须兼顾：

- 长时间编码的舒适度。
- 文字可读性。
- 选中状态辨识度。
- 鼠标悬停反馈。
- 文件树可读性。
- 多标签操作体验。

## 14. AI 编程工具执行规范

本项目可以使用 Codex 或其他 AI 编程工具辅助开发，但必须遵循以下要求。

### 14.1 先研究，再实现

AI 不得直接凭空生成完整主题。

首先需要：

1. 阅读 Sublime Text 官方主题文档。
2. 检查 Sublime Text 默认主题资源。
3. 研究 IntelliJ IDEA Islands 参考截图。
4. 建立视觉 Token。
5. 明确每个控件的实现方式。
6. 再开始编写配置。

### 14.2 不允许凭空编造 API

所有 Sublime Text 控件名称、属性、文件格式和配置项必须有官方文档或实际运行依据。

不能将 VS Code、JetBrains 或其他编辑器的属性直接应用到 Sublime Text。

### 14.3 不允许只生成文件不进行验证

每次修改后都应执行：

- JSON 格式检查。
- 文件路径检查。
- 资源映射检查。
- Sublime Text 实际加载检查。
- 截图检查。
- Dark / Light 切换检查。

### 14.4 采用小步迭代

不要一次性生成所有模块后才开始验证。

推荐顺序：

1. Dark UI Theme。
2. Light UI Theme。
3. Dark Color Scheme。
4. Light Color Scheme。
5. File Icons。
6. 切换方案。
7. 完整安装包。

每个阶段都需要通过验收。

### 14.5 不允许擅自降低视觉目标

如果某个控件难以还原，应先研究 Sublime Text 的实际能力，再给出可行替代方案。

不能为了快速交付而把项目退化成普通的深色配色主题。

## 17. 项目最终定位

本项目的目标是：

**在 Sublime Text 4 的原生主题机制和能力边界内，最大程度复现 IntelliJ IDEA Islands UI 的视觉体验。**

它不是普通的 JetBrains 配色主题，而是一套完整的视觉系统：

- 窗口 UI
- 标签栏
- 侧边栏
- 工具窗口
- 编辑器配色
- 文件图标
- Dark / Light 双主题
- macOS 适配
- 安装与切换机制

视觉还原度是第一优先级，第三方图标是允许且鼓励评估的实现方式，但必须合法、统一并经过适配。

最终交付应当是一个独立、完整、可安装、可切换、可验证和可持续维护的 Sublime Text 4 主题包。
